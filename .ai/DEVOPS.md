# DEVOPS — build, test, CI, release

> Engineer-owned. Every CI/CD change is recorded here first (`skill: ci_gate`).
> rein-app has a **hosted** pipeline (GitHub Actions), unlike `rein` itself (local CI, D-072).

## Commands
| Purpose | Command |
|---|---|
| Format check | `cargo fmt --all --check` |
| Lint | `cargo clippy --workspace --all-targets --locked -- -D warnings` |
| Test | `cargo test --workspace --locked` |
| Release build | `cargo build --profile dist` (cargo-dist profile) |

Order (hosted equivalent of the ci_gate step order): `fmt → clippy → test → build → release`.
Release runs only on version tags (E-6).

## Change log

### 2026-11-08 — E-2: initial CI matrix + cargo-dist config
**What / why**
- `.github/workflows/ci.yml`: on push to `master` and every pull request, run fmt, clippy
  (`-D warnings`) and `cargo test --workspace` on `ubuntu-latest`, `macos-latest`,
  `windows-latest`. Acceptance for E-2: green on all three.
- `Cargo.toml` `[workspace.metadata.dist]` (cargo-dist 0.34.0) declaring the five
  blueprint targets and a `dist` build profile. **No** `ci`/`installers` keys and no
  `release.yml` yet: the release workflow, Homebrew tap, `.deb`/AppImage and Windows
  installer are E-6. Adding `ci = "github"` before E-6 would make `dist` demand a
  generated release workflow.

**Security implications**
- No secrets. `permissions: contents: read` at workflow level; no write tokens.
- Only third-party action: `actions/checkout`, pinned to the commit SHA of v6.1.0
  (`d23441a48e516b6c34aea4fa41551a30e30af803`), `persist-credentials: false`.
  Toolchain installed with the runner's own `rustup`, no toolchain action.
- Network: crates.io only (no crate dependencies exist yet; `--locked` forbids silent
  lockfile drift once they do).
- `concurrency` cancels superseded runs on the same ref.

**Rollback**
- Delete or revert `.github/workflows/ci.yml`; nothing else depends on it.
- cargo-dist metadata is inert until a `dist` command runs; revert the
  `[workspace.metadata.dist]` / `[profile.dist]` blocks to remove it.

**Verification**
- Local (Linux x86_64): fmt, clippy and test run before commit.
- Hosted: remote `Vimurai/rein-app` (public) created 2026-11-08; first push run
  42512783295 green on ubuntu-latest, macos-latest, windows-latest. **E-2 acceptance met.**

### 2026-11-09 — E-6: release pipeline (built on branch `engineer/e6-release-pipeline`; publishing gated on rein P-50)
**What / why** (distribution.md §Components 7-8, §E-## Task Breakdown E-6)
- `.github/workflows/release.yml` generated by cargo-dist 0.34.0 (`ci = "github"`), run only
  on a pushed `v*` tag: build the five targets, attach archives + checksums to a GitHub
  release, publish the Homebrew formula to the tap. Windows: `installers = ["msi"]` for
  the launcher binary (phase 1 runs rein inside WSL).
- `.deb`: cargo-dist does not build it. A separate job after the dist build uses `cargo-deb`
  (Linux x86_64/aarch64). AppImage is out of Phase 1 (D-012). Each new tool
  passes `skill: dependency_gate` first.
- Build env `REIN_RELEASE_PUBKEY` (the minisign public key, not a secret) baked into every
  release binary (D-003, E-3 divergence 8). Without it `production_verifier()` is the
  Rejecting backend and every install fails closed.

**Operator prerequisites (not doable from the Engineer pane)**
1. rein's production minisign key pair (rein P-50); its public key goes into the workflow
   as `REIN_RELEASE_PUBKEY` (a repository variable, not a secret).
2. A tap repository (e.g. `Vimurai/homebrew-tap`) and a fine-grained token with
   contents:write on that repo only, stored as secret `HOMEBREW_TAP_TOKEN` in rein-app.
3. Install cargo-dist 0.34.0 locally to generate (and later `dist plan`-check) the workflow.

**Security implications**
- New secret `HOMEBREW_TAP_TOKEN`, used only by the publish job, only on tags.
- Release job needs `contents: write` (create the release); every other job stays
  `contents: read`. Third-party actions pinned by SHA as in ci.yml.
- A release built without `REIN_RELEASE_PUBKEY` must not be published: the workflow fails
  the build when the variable is empty (to add with the workflow).

**Rollback**
- Delete `release.yml` and the `ci`/`installers`/`tap` keys from `[workspace.metadata.dist]`;
  ci.yml is untouched. A bad release: delete the GitHub release and revert the tap commit.

**Verification plan**
- On a branch: `dist plan` locally, then a `v0.1.0-rc.1` tag on a fork or with publishing
  disabled; hosted run green on all targets before the first real tag.

**As built (2026-11-09)**
- Operator decisions: create the tap; build the pipeline now, guarded. `Vimurai/homebrew-tap`
  created (public, README only). Build tools recorded as D-010.
- `[workspace.metadata.dist]`: `ci = "github"`, installers shell/powershell/homebrew/msi,
  `tap`, `publish-jobs = ["homebrew"]`, `install-updater = false` (`rein-app update` is ours);
  actions pinned by commit via `github-action-commits` (checkout v6.1.0, upload-artifact
  v7.0.2, download-artifact v8.0.2). `crates/rein-app/wix/main.wxs` + `[package.metadata.wix]`
  GUIDs generated by `dist init` (keep the upgrade GUID stable forever).
- `.github/build-setup.yml` (cargo-dist `github-build-setup`): before every release build,
  fail unless repository **variable** `REIN_RELEASE_PUBKEY` is set and is one base64 line,
  then export it. PRs run only `dist plan` (no build), so the guard bites on tags only.
- `.github/workflows/build-linux-packages.yml` (cargo-dist `local-artifacts-jobs`): `.deb`
  for amd64/arm64 via cargo-deb 3.8.0, same key guard, uploads `artifacts-deb-*` for the
  release. Local check: `cargo deb -p rein-app` → `usr/bin/rein-app` only.
- **cargo-dist 0.34.0 bug**: it renders the local reusable job as `uses: $/.github/...`.
  `release.yml` line `uses: ./.github/workflows/build-linux-packages.yml` is a hand fix and
  `allow-dirty = ["ci"]` stops `dist` from failing on it. After any `dist generate`, re-apply
  that one line (grep for `$/.github`).
- **AppImage out of Phase 1** (D-012; D-010 named it first to drop): appimagetool publishes no versioned,
  checksummed release to pin. Homebrew + .deb + tarball cover Linux.

**Still needed from the operator before the first tag**

2. `REIN_RELEASE_PUBKEY` repository variable once rein P-50 publishes the key.
