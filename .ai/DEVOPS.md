## Commands
| Purpose | Command |
|---|---|
| Format check | `cargo fmt --all --check` |
| Lint | `cargo clippy --workspace --all-targets --locked -- -D warnings` |
| Test | `cargo test --workspace --locked` |

| Window UI (in `crates/rein-desktop/ui`) | `npm ci --ignore-scripts && npm run check && npm test && npm run build` — before building `rein-desktop` for use; without it the crate still compiles and tests (a placeholder page, with a cargo warning) |

### 2026-11-10 — E-16: release key guard reads the committed key file (ci_gate)

**What changes and why (D-014 decision 4 + addendum 2026-11-10).** The trust root moves from the `REIN_RELEASE_PUBKEY` repository variable to a committed file, `docs/contract/release-key.pub`. It is a byte-for-byte copy of rein's `docs/contract/release-key.pub` (same path as in rein, so the pre-tag comparison is a plain `cmp`). The binary bakes the file at compile time (`include_str!`), so CI, release and source builds all trust the same key, and rotation is a reviewable commit. The key guard step changes from "variable set and base64" to "file present and in minisign public-key format". It runs in three places: `.github/build-setup.yml`, its inlined copy in `release.yml` `build-local-artifacts`, and `build-linux-packages.yml` `deb`. The step no longer writes anything to `GITHUB_ENV`.

**Security implications.**
- No new secret, permission or network access.
- One fewer thing to configure: the repository variable is no longer read, and the operator need not create it.
- An injection path is removed: the old step copied a repository variable into `GITHUB_ENV`.
- The key is now public in git, which is its purpose. A malicious key swap would have to pass review as a commit touching `docs/contract/`.
- Remaining guard: before the first tag (E-6), `docs/contract/release-key.pub` must equal rein's file on `main` byte for byte (D-014 addendum). A difference blocks the tag.
- The `reject-all-signatures` cargo feature stays as the kill switch.

**Rollback.** Revert the E-16 commit. The build then reads `REIN_RELEASE_PUBKEY` again, and the operator must set that variable before a tag.

**Testing.** The guard steps only run on a tag push, so their shell logic is exercised locally against the real file, a missing file and malformed copies (results below). `release.yml`'s `plan` (PR mode) and `ci.yml` run on the push.

**Results (E-16)**

### 2026-11-10 — E-22: one tested key-file guard, a tag gate against rein's `main`, CODEOWNERS (ci_gate, D-017)

**What changes and why.**
- The key-file guard pasted into three places (E-16) moves to `.github/scripts/check-release-key.sh`. `.github/build-setup.yml` (and its inlined copy in `release.yml`) and `build-linux-packages.yml` call it with `bash`.
- New `.github/scripts/compare-release-key.sh A B`: exits 0 only when both files exist and are byte-identical.
- New tag gate: in `release.yml` `plan`, right after checkout and before dist is installed, and only on a tag push (`startsWith(github.ref, 'refs/tags/')`). It fetches rein's `main` copy over HTTPS (`curl --proto '=https' --tlsv1.2 -fsSL`, size-capped) into `$RUNNER_TEMP`, compares it with ours, and deletes it. A 404, a fetch error or any difference fails `plan`, so no artifact job runs.
- New corpus test `.github/scripts/test-release-key-scripts.sh` builds its fixtures in a `mktemp -d` directory from the committed key. It runs as a step in `ci.yml` on all three OSes, with no network.

**Security implications.**
- No secret is involved. One new network access happens on tag runs only: an anonymous GET of a public 113-byte file from `raw.githubusercontent.com`.
- The fetched bytes are compared and discarded; nothing is built from them, so the binary still never fetches a key (D-017 ruling 1).
- Pull-request runs never fetch.
- CODEOWNERS binds only when branch protection requires code-owner review. That is a repository setting, and the operator's call.

**Answers**
1. **The rc tag needs a version bump. Reported, not made.** Three manifest lines change: `[workspace.package] version`, and the two path-dependency `version`s in `crates/rein-app/Cargo.toml`. `Cargo.lock` changes in three entries too, and must be committed, because the release jobs build `--locked`.
2. **GitHub prerelease: yes.** `host` passes `--prerelease` when `announcement_is_prerelease` (release.yml `PRERELEASE_FLAG`).
3. **Homebrew publish: no.** `publish-homebrew-formula` runs only `if !announcement_is_prerelease || publish_prereleases`, and both are against it for an rc. So an rc needs no `HOMEBREW_TAP_TOKEN`; the final tag does.
4. **Package versions for the rc** (checked in the copy): `.deb` → `0.1.0~rc.1-1` (sorts before `0.1.0-1`, so the final `.deb` upgrades it). `.msi` → cargo-wix 0.3.9 maps `0.1.0-rc.1` to ProductVersion `0.1.0.1` and the final to `0.1.0`. **Windows Installer ignores the 4th field when comparing, so the final `.msi` does not major-upgrade an installed rc `.msi`** (two entries, or a refusal). Uninstall the rc `.msi` before installing the final one, or the Architect rules on a WiX change, e.g. `AllowSameVersionUpgrades`.
5. **The tag gate (E-22) runs for the rc tag too**, and fails until rein commits `docs/contract/release-key.pub` on `main`.

**Operator sequence** (every step is the operator's; no agent tags or pushes):
- Preconditions:

  - Hosted CI is green on the commit to tag.
